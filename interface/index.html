    Welcome to CardioKB

    CardioKB is a general-purpose biomedical knowledge graph integrating 32 data sources into a single queryable network. It connects genes, diseases, drugs, pathways, clinical trials, phenotypes, variants, and more — spanning all human diseases, not just cardiovascular.

    • 373K+ nodes across 18 entity types, 26M+ relationships from 25 sources
    • Search any disease (heart failure, Alzheimer's, cancer...) or any gene/drug
    • Add new databases instantly — the AI-powered DatabaseAgent writes the parser for you

    Explore & Query

    The Explore tab visualizes disease/gene subgraphs:

    • Search any disease or gene — type a name and click Explore
    • Core nodes (large, solid) are direct known associations
    • Discovery nodes (small, dashed) are 2-hop hypothesis-generating connections
    • Click any node to see its properties, neighbors, and specificity score
    • Use filter chips to show/hide entity types

    The Query tab gives you direct Cypher access — click a template or write your own (read-only, Cmd+Enter to run).

    Admin: Add New Databases

    Under Advanced in the sidebar, the Add New Database panel lets you expand the graph with any public data source:

    • Enter a database name and a direct download URL (TSV, CSV, JSON, or gzipped)
    • Click Build Parser — the DatabaseAgent (Claude AI) samples the file, generates a complete parser, integrates it into the pipeline, and loads the data into Neo4j
    • The agent handles format detection, column mapping, ontology config, and ID validation automatically
    • Three parsers already in production (HGNC, HGNC Families, ClinVar) were built entirely this way

    How to Read the Graph

    Two-layer architecture

    • Core layer — Direct (1-hop) neighbors of the searched disease. These are known, literature-backed associations from databases like DisGeNET, GWAS Catalog, and DrugBank. Shown as large nodes with solid borders.
    • Discovery layer — 2-hop neighbors reached through core nodes. These are hypothesis-generating connections not directly linked to the disease. Shown as small nodes with dashed borders and faded edges.

    Node sizing & shapes

    • Diseases are diamonds; all other types are circles
    • Core nodes are larger; discovery nodes are smaller
    • Colors indicate entity type (see legend below graph)

    Reading edges

    • Solid edges = core (known) relationships
    • Dashed edges = discovery (inferred) connections
    • Edge labels show the relationship type (e.g., ASSOCIATES_WITH, TARGETS)
    • Each edge carries a source property identifying the originating database
