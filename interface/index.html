    What is this graph?

    CardioKB is a knowledge graph — a structured map of known biological relationships relevant to cardiovascular disease. It connects genes, drugs, diseases, pathways, clinical trials, phenotypes, genetic variants, and more into a single searchable network.

    Every connection you see comes from a specific, peer-reviewed data source (DrugBank, ClinVar, STRING, PubTator, etc.). When you click on any edge (line), the panel on the right tells you exactly which database it came from and what evidence supports it.

    Disease-Specificity Score

    Not all gene–disease connections are equally meaningful. A gene linked to only 1 disease is far more informative for that disease than a gene linked to hundreds. The specificity score quantifies this:

    specificity = 1 ÷ (number of diseases a node connects to)
    • A gene linked to 1 disease scores 1.0 (highly specific — likely biologically meaningful)
    • A gene linked to 50 diseases scores 0.02 (broadly connected — may be a housekeeping gene)
    • Disease nodes themselves score 0.0; nodes with no disease connections score 1.0

    Why this matters: When investigating drug targets or biomarkers, high-specificity genes are more likely to represent a genuine disease mechanism rather than general cellular housekeeping. The graph prioritizes showing you the most specific nodes first.

    ML-Predicted Drug–Disease Links

    The cyan dashed edges are not from curated databases. They are machine learning predictions of drugs that might treat a disease, based on patterns in the knowledge graph.

    How the pipeline works
    1. Graph embedding — Two complementary methods learn numerical representations for every entity in the knowledge graph:
      • RotatE (256-dim) — Models relationships as rotations in complex vector space, capturing asymmetric and compositional relation patterns.
      • CompGCN (128-dim) — A graph neural network that jointly embeds nodes and relation types, learning from the full neighbourhood structure.
    2. Feature engineering — For each candidate drug–disease pair, we combine embedding-derived features (element-wise interactions) with graph structure features (shared neighbors, Adamic-Adar index, node degree).
    3. Classification — An XGBoost decoder (decision tree ensemble) was trained on known “drug treats disease” relationships to distinguish real therapeutic links from random pairs.
    4. Prediction — Each method scores all unknown drug–disease pairs. The top 500 predictions per method (confidence ≥ 50%) are stored in the graph. Enable “Show ML predictions” in the toolbar, then click any cyan edge to see which method produced it and the confidence score.
    Model performance (XGBoost decoder)

    Both methods were rigorously evaluated using an 80/10/10 stratified train/validation/test split with no data leakage (embeddings trained only on training edges):

    Metric RotatE CompGCN What it means

    Test AUPRC0.9660.971Precision–recall balance — few false positives among top predictions

    Dataset: 9,735 therapeutic drugs × ~480 diseases. 3,026 training / ~310 validation / ~325 test known “drug treats disease” edges. CompGCN achieves the best AUROC; ranking metrics (Hits@K) are comparable across methods.

    Important limitations
    • These are computational predictions, not clinical evidence. They suggest drugs worth investigating, not drugs to prescribe.
    • The model learns from graph structure (which entities are connected and how), not from clinical trial outcomes or patient data.
    • Predictions should be treated as hypothesis-generating leads for wet-lab validation, not as treatment recommendations.
    • The confidence score (shown when you click an orange edge) reflects the model’s certainty, not clinical efficacy. A 95% confidence means the model strongly believes this drug-disease pair resembles known treatments — it does not mean there is a 95% chance the drug works.

    Where does the data come from?

    CardioKB integrates 22 deduplicated data sources, each serving a specific purpose. Every edge carries a source property — click any edge to see exactly which database it came from. Key sources include:

    DrugBank — Drug-target binding interactions
    ClinVar — Clinically interpreted genetic variants
    STRING — Protein-protein interaction confidence
    PubTator — Gene-disease co-mentions in PubMed
    Reactome — Curated biological pathways
    ClinicalTrials.gov — Active and completed clinical trials
    HPO — Gene-to-clinical-phenotype mappings
    CTD — Chemical-gene expression interactions

    Explore & Query

    The Explore tab visualizes cardiovascular disease subgraphs:

    • Search any disease, gene, or drug — type a name, select from autocomplete, and click Search
    • Core nodes (large, solid) are direct known associations from curated databases
    • Discovery nodes (small, dashed) are 2-hop hypothesis-generating connections
    • Click any node or edge to see its properties, source database, and evidence
    • Use filter chips to show/hide entity types or edge types

    The Query tab gives you direct Cypher access to the CVD graph — click a template or write your own (Ctrl+Enter to run).

    ML Drug Repurposing Predictions

    CardioKB includes machine learning predictions of drugs that might treat cardiovascular diseases, generated using graph embedding methods:

    • RotatE and CompGCN embeddings trained on the knowledge graph, decoded with XGBoost (AUROC up to 0.972)
    • Toggle “Show ML Predictions” to overlay predicted drug–disease links as cyan dashed edges
    • Filter by method, view a sortable predictions table, and export results as CSV or JSON
    • Click any cyan edge to see the confidence score and which model produced it

    Important: These are computational predictions for research, not clinical recommendations. They identify drugs worth investigating, not drugs to prescribe.

    How to Read the Graph

    Knowledge graph

    • All nodes are direct (1-hop) neighbors of the searched entity, representing known, literature-backed associations from databases like OpenTargets, ClinVar, and DrugBank.

    Disease-specificity scoring

    • Every node has a pre-computed specificity score = 1 / (number of diseases it connects to)
    • A gene linked to only 1 disease scores 1.0 (highly specific); a gene linked to 500 diseases scores 0.002 (broadly connected, less informative for any single disease)
    • Disease nodes themselves score 0.0; nodes with no disease connections score 1.0
    • Use specificity to prioritize — high-specificity genes and drugs are more likely to be biologically meaningful for your disease of interest

    Node sizing & shapes

    • Diseases are diamonds; all other types are circles
    • The searched entity is highlighted with a white border and glow
    • Colors indicate entity type (see legend below graph)

    Reading edges

    • Solid edges = known relationships from integrated databases
    • Dashed cyan edges = ML-predicted drug–disease links (RotatE / CompGCN + XGBoost). Hidden by default — enable via the “Show ML predictions” toggle. Click any cyan edge to see method and confidence score. Not clinically validated.
    • Solid orange edges = disease hierarchy (subtype-of)
    • Each edge carries a source property identifying the originating database or model

    Thin results?

    • If a disease shows few connections, try a more specific CVD subtype name or increase the hop count in Extract Disease Subgraph.
